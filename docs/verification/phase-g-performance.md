# 阶段 G：第一轮性能基线与优化

日期：2026-11-15。阶段 A—F 功能完成后，开始统一性能测量。本轮完成核心与 Windows 宿主基线、第一轮优化和功能回归。阶段 G 继续推进。

## 环境与方法

Windows 10.0.26300，Intel Core i9-14900HX、32 个逻辑处理器、约 16 GB 内存；Node 24.22.1；Obsidian 1.15.0 运行包与 Electron 38.8.6。完整环境保存在原始 JSON。

Node 核心样例包括 200 KiB/1 MiB 多段落笔记、5000 行代码，以及一万篇合计 104860000 字节、五万条重点的合成索引。索引读源来自内存，分别测量冷建、未变内容热重建、单文件增量、全量条目读取、保留堆增量及定时器间隔。

宿主测量启用插件至索引就绪、200 KiB 标注至侧栏 DOM 更新、500 行代码展示更新、约 1 MiB/5000 行代码的选区事务及滚动请求提交。计时覆盖 DOM 就绪和强制布局；最终可见帧及滚动落点继续由兼容场景验证。隐藏宿主的帧等待会增加固定延迟，已从本组计时中分离。

核心每项运行 3—9 次，宿主每项运行 3—7 次，保存全部样本及最近秩 p50/p95。三次样本的 p95 为最大样本。优化前后顺序执行，使用同一设备、读源、样例与计时方法。宿主记录实际插件构建 SHA256；核心记录基准提交及源码差异摘要。

## 优化与结果

1. 正文范围按 AST 对应的行区间扫描；排除区间合并后一次拼接掩码，区间相交用二分查询。
2. 一次正文操作复用结构解析；同次侧栏刷新中，同一源文的卡片共享摘录上下文，并复用内容一致的索引条目。
3. 索引按约 8 ms 时间片通过 MessageChannel 让出线程，批量进度通知间隔约 100 ms，完成时发布最终状态。单文件编辑即时更新；内容未变时复用条目；卸载清空缓存。

| 场景 | 优化前 p50 | 优化后 p50 |
| --- | ---: | ---: |
| 200 KiB 结构解析 | 497.32 ms | 171.99 ms |
| 200 KiB 标注计划 | 1510.90 ms | 171.20 ms |
| 1 MiB 结构解析 | 8326.61 ms | 882.61 ms |
| 一万篇未变内容热重建 | 19756.10 ms | 47.07 ms |
| 200 KiB 标注至侧栏 DOM | 15270.40 ms | 2239.50 ms |

冷索引耗时从 15778.03 ms 变为 16491.05 ms；最大定时器间隔从 15846.95 ms 降至 37.15 ms；通知次数从每轮 10000 次降至 156—158 次。Node 冷索引保留堆增量的三组样本约为 119 MB，原始值见 JSON。

首轮使用计时器让出线程时，冷索引 p50 为 26462.0 ms；改用消息队列后降为 16491.05 ms。中间测量保存在 [首轮结果](performance/core-first-pass.json)。

全部指标，包括未改善项，见 [完整 p50/p95 对照](performance/comparison.md)。5000 行选区事务 p50 从 6.4 ms 变为 12.6 ms；500 行展示 p95 从 307.1 ms 变为 365 ms。下一轮增加采样并分离调度、布局和垃圾回收开销。

## 正确性验证

`pnpm check` 通过 30 个文件中的 180 项测试、lint、类型检查和构建。新增测试覆盖批量通知、让出线程时编辑优先级、热重建条目复用、卸载释放缓存、正文边界与共享摘录上下文。

[500 组差分样例](performance/parsing-differential.json) 与优化前解析器逐字段一致，覆盖 CRLF、UTF-16、表格、callout、围栏、HTML、注释及行内代码。

完整二十五条宿主功能回归共 638 项检查通过；性能场景另有 5 项正确性断言通过，页面错误收集为空。

# Highlight Boost 1.1.0 体验融合计划

日期：2026-11-16。更新：2026-11-17。状态：第一至第三阶段完成，第四阶段本地验收通过，三平台 CI 待执行。

## 1. 版本目标

1.1.0 以体验升级为主线，将现有标注、批注、代码展示、检索、集合、摘录和迁移串成连续流程，同时统一插件的视觉设计。

用户只需要理解“标注内容、记录想法、整理重点”。代码着色由插件统一处理，设置、命令和日常说明中移除“宿主 / Shiki”的选择，不再按引擎划分功能。

**代码体验广度至少达到 Shiki 所提供的水平，完整承接语言、参数、主题及展示交互能力。**

范围为 Obsidian 桌面端。实施内容包括统一代码体验、现有功能融合、界面升级、配置迁移与完整验证。

## 2. 当前体验与改进方向

以下依据 1.0.1 的源码和使用说明整理。

| 当前情况 | 1.1.0 的结果 |
| --- | --- |
| `syntaxProvider` 决定是否启用内置着色，需要重新启用插件 | 默认进入统一代码体验，移除提供者设置及切换提示 |
| 普通代码展示与内置代码组件有不同渲染结构 | 标题、行号、复制、折叠、标注和批注遵循同一套行为 |
| 工作台依次铺开范围、搜索、多个筛选和管理按钮 | 建立范围导航、搜索筛选、结果和操作四层结构 |
| 卡片承担较多操作，正文与代码的信息密度不同 | 统一卡片骨架，按内容类型呈现预览和上下文 |
| 标注后常要去侧栏继续添加批注、加入集合 | 在标注后就近提供下一步，侧栏继续承接完整管理 |
| 集合、摘录模板和导出与搜索控件混排 | 整理操作集中到集合入口与摘录面板 |
| 代码选项需要依靠文字理解效果 | 在设置中提供能即时变化的示例 |

## 3. 统一后的使用流程

### 3.1 从选中到整理

1. 选中正文、行内代码或代码块内容，显示相同风格的标注工具栏。
2. 选择重点、疑问、引用或行动，立即显示标注结果。
3. 工具栏转为当前标注的操作状态，可以继续改色、写批注、加入集合或移除标注。
4. 工作台同步更新条目；编辑批注或整理集合时继续使用同一条目标识。
5. 从当前结果或集合生成摘录，在提交前查看模板效果和结果数量。

新建标注后保持选区与阅读位置，不自动打开弹窗。批注和集合操作由用户主动点击。多选区操作保留一次撤销；后续独立编辑批注是单独的撤销步骤。

### 3.2 从检索回到原文

1. 打开统一的“高亮工作台”，默认显示当前笔记。
2. 切换当前目录、全库或集合，按需要添加筛选。
3. 点击结果打开原文、展开目标代码并短暂强调准确范围。
4. 返回工作台后保留查询、页码、展开项和滚动位置。

现有“当前笔记重点”和“高亮工作台”命令保留为快捷入口，进入同一视图并选择对应范围。

## 4. 统一代码体验

### 4.1 实现方向

以当前内置语法引擎作为统一着色基础，将其作为内部实现。代码展示层集中处理标题、行号、换行、折叠、复制、diff、用户标注及批注，消除两套代码组件的重复按钮、样式和状态。

编辑器通过 CodeMirror 接入着色与标注；阅读视图使用统一代码组件；实时预览在编辑代码与展示代码时采用同一套展示参数和视觉规则。不同视图的交互服从其用途：编辑器保留光标、选区和原生编辑折叠，展示组件提供标题栏与展示折叠。对应的内容、行号、标注和跳转结果一致。

未知语言、无语言代码块也使用统一外观，并以纯代码呈现。Mermaid 等由 Obsidian 或其他插件负责的图表、查询、交互块继续交给对应处理器，识别规则在第一阶段确认并记录。

### 4.2 用户可见行为

- 所有普通代码块默认获得一致的着色与展示能力，不需要选择或重启切换引擎。
- 标题栏采用一个复制主按钮；diff 的“复制原始 diff / 复制变更片段”在同一复制菜单中选择。
- 行号、标题、折叠、换行继续支持全局设置与围栏覆盖，围栏设置优先。
- 代码块中的高亮、批注数量和侧栏结果互相对应，点击标注摘要可打开该块的条目。
- 浅色、深色和主题切换时同步更新配色，保留语法结构和用户强调的可读性。
- 未知语言与超长行保持可阅读、可选择、可复制、可标注。
- 代码复制只输出代码；批注、行号和隐藏元数据继续排除在外。

### 4.3 升级处理

- 1.0.x 的 `syntaxProvider` 在加载配置时自动转换并退出运行时配置；原来两种取值都进入统一体验。
- 保留语言、语义预设、最近颜色、集合、摘录模板和代码展示设置；现有默认展示开关保持原值。
- 不因升级批量改写笔记。正文高亮、脚注、行内代码和代码块标注继续读取现有格式。
- 原着色方式用户升级后会看到统一配色，正式发布日志明确说明这一变化。
- 旧配置转换只承担本次升级；代码中移除按提供者分支的长期维护路径。

### 4.4 代码能力覆盖基线

分别核对 Shiki 语法引擎、Shiki Highlighter 的桌面代码体验及当前集成的 Expressive Code 展示能力，形成代码验收矩阵。现有能力完整保留，对照发现的语言、主题、参数及展示交互差距在本版补齐，每项对应实现入口和验收样例。

| 能力维度 | 覆盖要求与验证方法 |
| --- | --- |
| 语言与别名 | 保留 Shiki 的完整语言覆盖、别名和大小写处理，逐项核对注册及实际入口；语法内嵌语言和多行状态使用代表样例验证 |
| 语法精度 | 保留 token 前景、斜体、粗体和下划线等样式，覆盖字符串、注释、多行结构、模板字符串和混合语言；编辑与阅读的语义结构一致 |
| 主题与配色 | 承接 Shiki Highlighter 的主题、配色及自定义能力；保留当前 Obsidian 主题变量映射与深浅色响应，设置按外观组织 |
| 代码框架 | 覆盖代码框、终端框、自动识别与无框样式，以及标题、文件名、复制和相应围栏覆盖；统一标题栏时保留框架语义 |
| 行与文本强调 | 保留普通行、增删行、带标签行范围、文本及正则标记，与 HB 人工语义标注叠加；原有有效参数继续生效 |
| 折叠 | 同时保留整块折叠和 `collapse={2-3}` 等局部区段折叠，验证展开、复制、标注定位与折叠状态的配合 |
| 布局与编号 | 保留标题、起始编号、逻辑行号、行号字体、长行换行与横向滚动，覆盖围栏覆盖和多行折行 |
| diff 与原文 | 保留 diff 展示、原始 diff 和变更片段复制；首行注释、终端注释、空白和原文映射遵循既有复制约定 |
| 离线与生命周期 | 已提供的语言和展示能力离线可用；按需加载、窗口主题、重载和资源释放纳入统一实现 |

能力矩阵每行记录来源、参数或设置入口、1.0.1 实际行为、1.1.0 对应入口、适用视图和验证结果。先固化旧内置路径的输入样例与行为，再实现替换；比较内容、操作和显示效果，不要求保留旧 DOM 结构。

统一展示层承接代码框架、文本 / 正则强调和局部折叠。图表、查询等专用处理器单独记录归属；普通代码语言按语言覆盖矩阵提供语法着色。

发布前代码能力矩阵全部通过，覆盖现有能力和上游对照的补齐项。

## 5. 界面与视觉升级

### 5.1 统一视觉规范

整体风格采用简洁、轻量的 Obsidian 原生界面：使用主题变量、清晰的文字层级、适量留白和轻边框。语义色用于标注、标签与局部强调，不将整张卡片铺成高饱和色块。

建立统一的间距、圆角、字号、图标尺寸、按钮高度、边框和交互状态变量。正文预览使用界面字体，代码预览使用等宽字体；来源路径与行号降低视觉权重，语义名称和摘录内容优先。

组件覆盖默认、悬停、选中、展开、键盘焦点、处理中和空状态。操作反馈尽量在发生位置呈现，例如复制按钮显示成功反馈、保存批注后更新摘要。

### 5.2 工作台布局

从上到下组织为：

1. **范围栏**：当前笔记、当前目录、全库、集合，以及当前来源名称。
2. **搜索栏**：搜索输入与筛选入口；已启用条件显示为可移除标签，提供清空筛选。
3. **结果栏**：条目数量、分组方式与摘录入口。
4. **结果列表**：统一卡片，保留现有分页能力。

类型、语义、颜色、语言和路径集中在可展开的筛选区；集合管理只在集合范围显示；重建索引放进更多菜单。索引进度采用轻量状态提示，读取失败时提供具体状态和重试入口。

窄侧栏以单列布局为主，宽工作台增加预览空间。筛选区、菜单与弹窗根据实际容器宽度调整，独立窗口采用相同行为。

### 5.3 结果卡片

- 头部：语义图标与名称、内容类型，主要操作保持稳定位置。
- 主体：正文摘录或代码片段，命中内容清晰可见；批注显示简短摘要。
- 底部：来源笔记、标题链和代码行号；长路径折叠展示，悬停可查看完整路径。
- 展开后：查看完整批注、相邻代码上下文和更多操作。
- 常用操作：定位、批注、复制；改语义、改颜色、集合和移除统一进入更多菜单。
- 待重新定位的条目保留摘录并就近提供重新绑定入口。

空状态分别处理尚无标注、筛选无匹配、空集合和未打开笔记，分别提供创建提示、清空筛选、添加条目或打开笔记等动作。

### 5.4 选区工具栏与批注

工具栏主层保留四种语义和颜色入口。只有代码选区显示“精确 / 整行”；多选区显示处理数量，混合选区说明处理对象。

选择已有标注时显示其当前语义与颜色。应用后允许继续写批注、加入集合或移除，减少重复寻找条目的步骤；重叠标注时先明确选择目标条目，再执行条目操作。

批注编辑采用统一轻量面板，提供原文摘要、多行输入、保存和取消；工具栏与工作台使用相同的编辑服务。打开、取消和保存后焦点回到触发位置。

### 5.5 设置页

按“标注与工具栏、代码展示、工作台与摘录、语言与数据”分组。预设名称与颜色并排编辑，代码展示旁使用包含语法、精确标注、整行标注和批注的示例。

设置变化即时更新预览和已打开视图。导入迁移保留独立向导入口，技术来源与许可进入说明链接。

## 8. 验收标准

### 功能融合

- 全新安装与两种旧 `syntaxProvider` 配置升级后，进入相同代码体验；用户界面无提供者选择或重启切换提示。
- 代码能力矩阵全部通过：完整语言与别名覆盖、主题与自定义配色、文本 / 正则标记、终端框和局部折叠均可使用；逐项对照记录随版本归档。
- 正文、行内代码、代码精确范围、代码整行与混合多选区均能标注、改色、改语义和撤销 / 重做。
- 从工具栏创建标注、添加批注、加入集合、检索、定位和生成摘录，完整流程可连续完成。
- 重叠代码标注可逐条编辑或移除；旧批注、集合引用和重新绑定行为保持正确。
- 搜索与筛选覆盖完整结果，摘录预览数量与实际输出一致，切换页码不影响导出范围。
- 迁移预览、颜色映射、应用、重启后逐文件恢复及完成后查看结果正常。

### 展示与交互

- 编辑器、实时预览和阅读视图的代码内容、逻辑行号、围栏参数、标注与复制结果一致；标题栏无重复按钮。
- 深浅主题切换、未知语言、无语言代码、diff、长代码、嵌套引用与 Callout 按样例检查；图表和查询块继续使用对应处理器。
- 在 280、360、600 像素宽的工作台检查布局，搜索、筛选、结果、菜单和弹窗无横向溢出或遮挡；长代码在其自身区域滚动或换行。
- 默认主题及现有主题 / 插件共存矩阵重新检查，重点核对配色、双重渲染与处理器归属。
- 键盘可以完成工具栏操作、条目定位、批注、集合选择和摘录；Escape 与焦点返回规则一致。中文输入法组合输入不触发标注动作。
- 主窗口与独立窗口的设置、主题和语言同步更新；各工作台保留自己的查询、滚动和来源上下文。
- PDF 导出保留颜色、代码标注和批注，隐藏元数据不进入成品。

### 升级与工程

# 阶段 G：实际文件索引与大量结果展示

日期：2026-11-15。环境：Windows 11、Obsidian 1.15.1、Electron 43.8.9、Intel Core i9-14900HX、约 16 GiB 内存。

## 场景与测量

独立测试库包含 **10,000 份实际 Markdown 文件，共 104,860,000 字节**，每份 10,486 字节、一个标题和一条唯一高亮。准备脚本、库和用户目录均在项目内，样例由 Git 忽略。普通功能测试继续使用原测试库。

磁盘冷索引每次新建同一 `HighlightIndex`，通过真实宿主 `Vault.read` 读取一万份文件，绕过 `cachedRead` 的应用层缓存。每个样本实际调用 10,000 次读取，校验最终笔记数、条目数和错误数；三个样本各有完整检查。操作系统文件缓存保留，冷指插件索引为空。热重建沿用已有索引并核对未变条目的对象复用。增量样本实际修改单篇笔记并核对最新条目，最后恢复原文。

前后测均使用同一文件集、宿主版本和设备，各指标三次采样。UI 计时包含同步刷新及强制布局，以 DOM 就绪为终点。基线插件来自 `8e326f8`；原始结果记录构建 SHA256。p50/p95 取最近秩，三次采样的 p95 为最大值。

## 大量结果展示

工作台原来为所有命中创建卡片和摘录上下文。1,000 条查询的刷新中位耗时为 3775.5 ms。本轮改为每页 50 条，仅为当前页创建卡片与上下文，完整命中集继续用于搜索、计数和导出。

| 场景 | 前测 p50 / p95 | 后测 p50 / p95 |
| --- | --- | --- |
| 1,000 条查询结果刷新 | 3775.5 / 3823.4 ms | 187.5 / 188.8 ms |
| 1,000 条范围内精确筛选 | 22.0 / 32.3 ms | 19.3 / 20.7 ms |
| 当前创建的卡片数 | 1000 | 50 |

同一 1,000 条查询的刷新中位耗时减少约 **95.0%**。后测额外运行完整 **10,000 条查询**，刷新 p50 为 **194.9 ms**、p95 为 **196.1 ms**，当前仍创建 50 张卡片。基线未运行完整一万条卡片展示，该项作为新增规模验收记录。

分页提供来源与语义分组、上一页/下一页、页码和条目范围。筛选、排序及范围变化回到首页；同一查询刷新保留页码，结果减少时调整页码；ItemView 状态保存页码。翻页后键盘焦点移到可操作的分页按钮。中英文文案即时更新。

## 实际文件索引基线

索引核心沿用上一轮实现。本组数据用于建立实际文件读取、调度与资源占用基线。

| 场景 | 前测 p50 / p95 | 后测 p50 / p95 |
| --- | --- | --- |
| 一万篇冷索引 | 36.30 / 39.08 秒 | 34.68 / 35.93 秒 |
| 一万篇热重建 | 1.759 / 1.804 秒 | 1.490 / 1.505 秒 |
| 单篇实际修改及增量索引 | 18.9 / 24.3 ms | 20.2 / 23.4 ms |

后测三个冷索引样本的最长 10 ms 定时器间隔分别为 **30.3 / 26.1 / 19.2 ms**，进度通知分别为 344 / 336 / 335 次。索引结束时采集 V8 已用堆，原始数据保留每次读数；该指标包含当时尚未回收的分配，后续补充回收后保留量和启停曲线。

本轮索引计时使用独立源和进度计数回调；生产环境中的侧栏随进度更新、启动阶段及磁盘缓存组合继续纳入后续测量。

## 正确性与证据

分页专项通过 25 项宿主检查，覆盖首页/末页边界、翻页顺序、焦点、筛选和排序、页码恢复、结果减少、中英文、跨页来源分组、完整导出和卸载。专项从第 2 页发起导出，核对传入全部 123 条命中，并验证生成笔记包含首条与末条内容。

大库后测 15 项检查通过，页面错误为空。188 项逻辑、DOM 与引擎测试通过；二十六组完整宿主回归共 663 项检查通过。最终 `main.js` 的 SHA256 与性能后测一致。分页画面已核对，原有阶段截图保留历史版本。完整功能回归见[验收矩阵](phase-g-matrix.md)。

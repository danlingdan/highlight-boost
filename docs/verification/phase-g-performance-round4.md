# 阶段 G：重建期间响应与资源释放

日期：2026-11-15。宿主：Obsidian 1.15.1 / Electron 43.8.9，Windows，沿用第三轮设备。

## 工作台打开期间重建

独立测试库包含 1000 份实际文件，共 10,486,000 字节。每次新建同一 `HighlightIndex`，通过真实 `Vault.read` 读取文件，变更通知接入生产使用的 `refreshPanels()`。工作台全程打开，索引到 100 篇后执行搜索、清除筛选并聚焦翻页按钮。每组运行三次，采集 10 ms 定时器最长间隔、输入耗时、最终结果、卡片和焦点保留情况。

| 指标 | 前测 | 最终后测 |
| --- | --- | --- |
| 重建 p50 / p95 | 65.77 / 88.20 秒 | 4.10 / 5.45 秒 |
| 三次最长定时器间隔 | 256.1 / 231.4 / 267.9 ms | 114.0 / 24.0 / 43.5 ms |
| 三次搜索操作耗时 | 6.4 / 13.6 / 14.1 ms | 5.6 / 10.4 / 18.3 ms |
| 原卡片与焦点保留 | 三次均未保留 | 三次均保留 |

重建中位耗时减少约 93.8%。旧实现每次通知都重建当前页，刷新耗时又触发下一次进度刷新。现在根据源文、条目身份、来源视图、语言、预设、集合及查询条件复用当前页卡片，计数和翻页控件单独更新。下拉选项相同则保留节点。摘录上下文按最近使用顺序保存，最多 50 份源文。

第一次后测仍有 114 ms 的最长间隔，可见帧、滚动和活动笔记尾延迟继续进入阶段 G 的统一收尾。操作系统文件缓存保留，计时终点为 DOM 和强制布局完成。

## 卸载与堆引用

专项发现卸载插件时工作台叶片仍在，关闭清理未执行。现在卸载时显式关闭工作台；关闭后清空命中、渲染、控件、来源和摘录引用，后续刷新保持关闭状态。

堆快照还定位到构建时执行的 Expressive Code 交互脚本：它注册全局事件、MutationObserver 和 ResizeObserver，插件卸载没有释放，监听器引用整个模块作用域，导致每次启用后脚本后备存储增加约 11 MB。

新实现由 `SyntaxRuntime` 管理每个文档的复制、反馈、滚动区域和观察器，只处理带 HB 标识的代码容器。组件卸载或窗口关闭时移除监听、取消定时器、断开观察并清理反馈。尺寸回调将属性更新放到下一任务，观察目标移出 DOM 后取消观察。使用当前 Clipboard API，交互在内置语法组件初始化时启用。

三次循环均执行启用、打开工作台、选择文本和卸载，应用宿主编辑器选项后，通过 CDP 强制回收并检查 WeakRef。原生与 Shiki 各 25 项检查通过，三次的旧插件实例和工作台实例均为零。

| 后备存储（十进制 MB） | 基线 | 第一次 | 第二次 | 第三次 |
| --- | --- | --- | --- | --- |
| 修复前，原生 | 18.29 | 29.51 | 40.71 | 51.92 |
| 修复后，原生 | 7.0864 | 7.0869 | 7.0869 | 7.0869 |
| 修复后，Shiki | 18.2983 | 18.2998 | 18.2998 | 18.2998 |

回收后的 JS 已用堆：原生 15.98→16.54 MB，Shiki 18.29→18.96 MB。原始记录包含宿主 DOM、监听器及后备存储读数，快照原文件保存在忽略目录 `.bench-cache/`，分析脚本输出强引用路径。

# 实施阶段

每个阶段通过交付物和验收条件推进。四轮原型已覆盖编辑、锚定、语言对照、连续跨正文与代码选区，以及源码合入的内置 Shiki。截图归档与格式冻结继续收尾；阶段 B 已建立工程检查、CI、配置迁移及中英文界面，可编辑四种语义的名称与颜色。语言证据见 [中英文验证记录](../verification/i18n.md)，原型证据见 [第四轮验证记录](../verification/phase-a-iteration-4.md)。

阶段 C 已补齐行内代码闭环与正文持久语义，三类对象共享语义入口，直接改色保留已有语义。证据见 [正文语义记录](../verification/prose-semantic.md)，行内代码见 [专项记录](../verification/inline-code.md)。桌面选区面板及当前笔记侧栏搜索、筛选、逐条修改已接入，见 [选区与侧栏验证记录](../verification/selection-toolbar.md)。下一项为阶段 D 逐项验收及操作说明；完成后进入阶段 E 全库检索与摘录。

当前范围为桌面端，正式版发布前不承诺移动端支持；正式版之后再评估。阶段 A—F 完成功能及正确性验证，阶段 G 在功能完成后统一进行兼容验收、性能测试和优化。

自动化宿主测试通过隔离 Electron、JavaScript、官方 CLI 或 CDP 接口完成。

## 阶段 A：正文与代码技术原型

目标：把决定整体架构的行为做成可运行实验。

工作项：

- 搭建含正文、行内代码、多语言代码块、列表、引用和 callout 的样例库。
- 验证原生六色格式、默认色身份及当前版本下的 DOM 输出。
- 验证正文选区拆分、改色、多选区和单次撤销。
- 实现代码块逻辑行/列映射、围栏外元数据的识别和序列化实验。
- 对比阅读视图代码行容器与背景层两种方案，验证跨 token 精确标记。
- 验证围栏内插入行后的 quote 锚定、重复代码块识别和编辑器位置映射。
- 比较宿主着色与 Shiki 协作的显示、语言覆盖和复制行为。

交付：原型代码、样例库、截图、功能验证记录、HB schema v1 草案及选型记录。

验收：正文和代码在真实宿主中完成标记、改色、撤销、跳转；代码复制逐字符一致；元数据在列表及 callout 中有可复现结果。将结论写入决策文件后冻结首版格式。

## 阶段 B：工程基础和数据模型

依赖：阶段 A 的格式、渲染路线与最低版本结论。

工作项：TypeScript/esbuild 项目、manifest、锁文件、lint/typecheck/build；统一对象、解析接口、纯编辑计划；配置 schema 迁移；中英文文案；CI 和隔离测试库。

交付：可加载插件骨架、稳定接口、开发说明、基础测试及 CI。

验收：全新安装、启用、停用、重启均完成；命令可见；构建产物满足 Obsidian 格式；同一目录多次初始化配置保持一致。

## 阶段 C：正文与代码编辑核心

依赖：阶段 B。

工作项：

- 原生正文高亮、精确选区拆分合并、应用/切换/移除操作。
- 行内代码识别和重点表示。
- 代码块单行、多行、多段行及精确文本标记。
- 所有动作共用语义预设、EditPlan 和一次事务。
- 代码锚点实时映射、持久 quote 重定位、重复 ID 处理。
- 命令、右键菜单及桌面选区面板接入。

交付：可操作的正文和代码核心、格式样例、编辑与撤销测试。

验收：P01—P06、P09 对应操作通过；正文边界外内容保留；代码内容保持原样；多选区操作一次撤销；重启后代码标注和语义恢复。

## 阶段 D：三视图渲染和首个可用版本

依赖：阶段 C。

工作项：编辑、Live Preview、阅读视图的重点显示；主题变量；语法 token 协作；当前笔记侧栏；代码和正文定位；纯代码与基本摘录复制。

交付：覆盖全部 P0 的内部可用版本、桌面操作说明、功能验收记录。

验收：正文和代码标注在三视图切换中一致；长行、空行、跨 token 文本显示正确；当前笔记侧栏即时更新；定位准确；复制及撤销满足样例标准。

## 阶段 E：全库检索、集合和摘录

依赖：阶段 D。

工作项：增量队列与缓存；目录/全库范围；类型、语义、语言、路径过滤；集合清单；摘录模板；来源链接；代码上下文与行号；文件夹重命名处理。

交付：统一高亮工作台、可重建索引、可追溯摘录、功能验证记录。

验收：正文与代码出现在同一查询结果；变更只更新对应文件；改名后来源正确；索引重建与增量更新结果一致；导出笔记的源链接可回到对应位置。

## 阶段 F：批注、展示增强与迁移

依赖：阶段 E；展示增强也可在阶段 D 后按模块接入。

工作项：正文脚注和代码批注；标题、行号、折叠；diff 展示；Highlightr/Hilo 导入；Code Styler/Codeblock Customizer/Hugo/Expressive Code 参数适配；迁移预览和逐文件恢复。

交付：完整公开版候选、迁移工具、格式对照样例、批注导出。

验收：代码折叠后能跳转展开，复制仍准确；迁移同一输入重复执行结果一致；预览数与实际变更数相符；恢复后源文件内容匹配；批注重启可读并随摘录导出。

## 阶段 G：统一测试、性能优化与发布验收

依赖：阶段 F 完成，计划发布的 P0/P1 功能已具备。

工作项：Windows/macOS/Linux；最低版本与当前稳定版本；默认/Minimal/AnuPpuccin 主题；Shiki、代码美化、Style Settings 与摘录相关插件共存；多窗口、PDF 导出与可访问性检查。统一测量启动、解析、代码渲染、侧栏、索引和内存，基于基线定位瓶颈，完成优化后运行同组性能对照与功能回归。

交付：桌面平台矩阵、性能基线与优化前后对照、功能回归结果、复现样例、发布候选产物、用户手册。

验收：核心矩阵均有真实运行证据；统一性能测试完成，已识别的发布阻塞瓶颈处理完毕并有对照结果；优化后功能回归通过；CI 通过；安装包和源码版本一致；P0/P1 的完成状态逐项可查，公开版功能与文档对应。

## 阶段 H：开源发布与社区上架

依赖：阶段 G。

工作项：完善 README、LICENSE、示例及贡献说明；核对 ID；创建版本 tag 与 GitHub Release；上传 `main.js`、`manifest.json`、`styles.css`；通过 Obsidian Community 目录提交并处理自动审核反馈。

交付：公开可安装版本、发布说明、社区条目和后续问题模板。

验收：从 Release 下载后全新安装成功；manifest、tag 和产物版本相同；社区安装入口可用后记录上架状态。公开源码仓库与可安装版本分别记录。

## 阶段 I：扩展能力

依赖：公开版反馈与对应技术实验。

按需求选择复习队列、临时规则高亮、独立 Shiki 展示、PDF/EPUB 来源卡片、复杂导出及公开查询接口。每项扩展补充使用场景、格式兼容和验收样例，再纳入开发。

## 依赖与首版边界

```mermaid
flowchart LR
  A[原型] --> B[工程基础] --> C[正文与代码核心]
  C --> D[三视图和首个可用版] --> E[检索与摘录]
  E --> F[批注与迁移] --> G[统一测试与性能优化] --> H[发布]
  H --> I[按需求扩展]
```

首个可用版截止阶段 D，包含正文与代码两条主线；完整公开版完成阶段 H。功能正确性随开发验证；性能测试与优化在阶段 A—F 的计划功能完成后，于阶段 G 统一开展。

# 正文语义标注 v1

正文颜色沿用 Obsidian 原生 `==` 和六色 emoji。应用“重点、疑问、引用、行动”等语义时，在闭合高亮后紧贴一条隐藏注释：

```markdown
==🟡核心观点==%%hbp:{"v":1,"id":"prose-example","semantic":"important","label":"重点"}%%
```

## 字段与附着关系

- `v`：格式版本，当前为 1。
- `id`：持久标注身份。
- `semantic`：预设 ID，保持独立于名称和颜色。
- `label`：最近一次应用语义时的名称快照。

颜色从原生高亮读取，语义从相邻注释读取。预设改名、改色影响后续操作；已有笔记保留原快照。再次应用语义时更新快照，完整覆盖一条已有标注时保留其 ID。

附着关系由紧邻位置确定。原生高亮被手动修改颜色或内容后，相邻语义仍保留；与高亮分离的注释作为源文本保留。格式无效的注释也保留原样，对应高亮按原生颜色读取。

## 编辑规则

- 应用语义：设置选中范围的语义、名称快照和预设颜色。
- 直接改色：保留已有语义与名称快照，只更新原生颜色。
- 局部应用另一语义：拆分旧高亮，选区外继续保留原语义。
- 局部移除：移除选区内高亮和语义，保留两侧片段。
- 合并选择：选中多个片段后应用语义，生成合并后的标注。
- 拆分后的片段使用独立 ID；编辑复制出来的标注时，为后面的副本分配新 ID。
- 仅使用颜色命令创建的新正文高亮保持原生格式；之后应用语义时写入注释。

正文、行内代码和代码块的直接改色操作遵循同一原则。代码中的纯颜色标注继续更新自己的颜色名称；已有语义标注保留名称快照。

JSON 中的 `%`、`|` 和反引号分别编码为 `\u0025`、`\u007c`、`\u0060`，用于保持注释、表格和 Markdown 结构。所有编辑通过同一 `EditPlan` 和宿主事务完成，保持撤销与重做。

## 三视图与侧栏

Source 显示完整注释。Live Preview 将编辑器中的注释收起为“正文标注”，键盘或鼠标可展开。阅读视图使用原生高亮，注释按 Obsidian 规则隐藏。

侧栏读取持久语义 ID 和名称快照，点击后选中正文内容本身。统一条目接口的 `semantic` 提供语义 ID，`markId` 提供持久标注 ID；纯原生正文高亮继续使用颜色名称。

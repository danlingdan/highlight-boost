# 代码块专项方案

## 1. 能力分层

| 层 | 负责内容 | 首版实现 |
| --- | --- | --- |
| 语言层 | 关键字、字符串、注释、类型的语法颜色 | 复用宿主，验证 C/C++、Python、JS/TS、JSON、Bash、汇编 |
| 重点层 | 用户选择的行、文本、参数、表达式 | HB 统一语义，背景、底线、左侧标记 |
| 讲解层 | 与某段代码关联的解释 | 侧栏批注、定位、带解释摘录 |
| 展示层 | 标题、语言、行号、折叠、diff | 模块化开关，完整公开版集成 |

首版同时包含行级与精确文本标注。语言层选型以实际覆盖表为依据：`asm`、`nasm`、`x86asm` 等别名逐一验证并提供映射；未识别语言保留纯文本代码展示，重点层照常工作。

## 2. 存储方案比较

| 方案 | 优点 | 维护特点 | 结论 |
| --- | --- | --- | --- |
| 在代码内插入 mark 或 `==` | 直观看到标记 | 改变代码文本，影响复制和语言解析 | 用于示例展示研究 |
| fence 参数，如 `hl:2,4-6` | 行级简洁，已有生态 | 精确列、批注和稳定 ID 需要额外结构 | 导入与导出适配 |
| 代码注释指令 | 可关联语言语法 | 每种语言注释不同，可能原本就是代码 | 按来源显式导入 |
| 插件 JSON sidecar | 笔记正文简洁 | 文件移动、跨设备同步需关联数据 | 保存缓存与临时状态 |
| 紧邻围栏的版本化 Markdown 注释 | 与代码一起移动，支持完整范围 | 需要源映射与嵌套容器规则 | **首选原型方案** |

## 3. 拟定 HB v1 格式

以下为本项目格式提案，原型通过后冻结。元数据位于代码块前方，同一容器层级，紧邻围栏；逻辑行从 1 开始，列偏移从 0 开始，范围为左闭右开。

````markdown
%%hb:{"v":1,"blockId":"cb-example","marks":[{"id":"m-1","kind":"lines","from":2,"to":3,"semantic":"important"},{"id":"m-2","kind":"text","line":2,"from":14,"to":17,"quote":"src","prefix":"(dst, ","suffix":", n)","semantic":"question"}]}%%
```c
void copy(char *dst, const char *src, size_t n) {
  memcpy(dst, src, n);
}
```
````

`lines` 的 from/to 表示 `[2,3)`，即第 2 行；文本标记指第 2 行中从列 14 到列 17 的 `src`。运行时核对 quote 和上下文。多行精确文本拆成多个 segment，统一 mark ID；字段细节在 schema 冻结时补齐。

注释包含 schema 版本、blockId、标注 ID、范围、quote/上下文、语义 ID 及必要的语义展示快照。可选 comment 记录文本。序列化对换行及 `%` 做 JSON Unicode 转义，正文中出现 `%%` 时仍保持 Obsidian 注释边界完整。

列表与引用中的注释沿用相同缩进/引用前缀，匹配发生在剥离容器前缀之后；保留源映射，将代码逻辑列换算回原文列。紧邻关系允许的空行数量、围栏参数顺序和多元数据记录合并规则在原型中定稿。

关闭插件后，围栏与代码保持标准 Markdown；HB 注释保留标注信息。输出给其他 Markdown 渲染器时，可选择去除 HB 注释或转换为目标 fence 参数。代码剪贴板直接读取源文本内容。

## 4. 行级标记

支持单行、范围、多段范围和多色语义。用户选择代码行后执行命令，插件生成元数据。可选块内相对行号与起始显示行号；标注始终按块内逻辑行定位。

软换行时一个逻辑行可以占多行屏幕高度，背景覆盖其完整展示高度；空行也可标记。折叠后标题显示标注数量和语义摘要，跳转时展开并滚入目标。

优先级：当前交互选区 > 精确文本强调 > 行背景 > 原始代码背景。语法 token 前景保持可读；多个语义在左侧以并列标记表达。

## 5. 精确文本标记

支持函数名、变量、参数、地址、常量和跨行表达式。位置按源代码字符范围记录，结合 quote 核对，显示时跨语法 token 拆分包装。相交标注共享背景合成规则，各自保留 ID 与批注。

正文选区和代码选区使用相同语义面板。针对含 Tab、中文、emoji 的代码，列计算使用 UTF-16；操作选区按用户实际选择，显示列由编辑器换算。

## 6. 编辑与阅读实现

**编辑器**：在原生代码块内容上增加 CM6 line/mark decorations，光标和输入继续由原编辑器处理。Source 模式显示元数据原文，可提供折叠入口；Live Preview 可将已解析 HB 注释收起为可展开标记。注释折叠涉及 replace decorations，需验证光标、选区和视口布局。

**阅读视图**：接收宿主 `pre > code` 的渲染结果；通过源映射找到相应代码块。遍历代码文本节点建立偏移映射，对所需区间添加标注。行背景实现比较“保持 token 树的行容器”和“独立背景层”，以跨行注释、软换行、主题和复制表现选择。

宿主和第三方渲染器可能异步重建 DOM。每个代码块绑定局部生命周期；重复渲染先清理本插件结构再应用，保持幂等。观察器限定在已识别的代码容器，性能记录覆盖重渲染次数。

## 7. 语法着色选型

首版使用宿主着色，建立 token 类与人工强调的 CSS 关系。Shiki 单独做实验：按语言和主题加载，复用高亮器实例，比较 JS/WASM 正则引擎、初始化耗时、包体与移动内存。具体 API 和版本在实现时依据锁定依赖确认。

提供“宿主语法 + HB 重点”“第三方语法 + HB 重点”“HB 独立代码展示”三种模式的架构空间。首版优先前两种，独立展示由引擎实验决定。对于 Shiki Highlighter、Code Styler、Codeblock Customizer 共存时，按代码展示模块选择唯一样式拥有者，HB 保留语义和侧栏能力。

## 8. 行号、复制、折叠与代码批注

- 行号：只显示逻辑行，可单独设置字体和起始数，复制读取源文本。
- 标题：来自用户设置或 fence 文件名字段，语言图标采用本地资源。
- 折叠：记住会话状态，跳转自动展开；编辑全文不依赖折叠组件。
- 复制：提供整个代码块、精确选区及带解释摘录三个按钮/命令。
- 批注：点击侧栏条目编辑说明，代码旁展示标识，可切换展开说明。
- diff：增删属于代码变化属性，疑问/重点属于阅读语义，分别渲染；复制支持原始 diff 与去前缀代码两个明确动作。

## 9. 解析与导出边界

四反引号包含三反引号、波浪线围栏、callout/引用/列表、空语言、未闭合围栏和代码内 HTML 都有固定样例。未闭合围栏按宿主展示状态解析，元数据操作显示实际识别到的范围。

`mermaid`、`dataview`、`tasks` 等处理器负责的围栏由各自渲染器管理；HB 默认只增强实际展示为源代码的块，原始源码标注可从 Source 模式创建并由侧栏访问。语言排除表可配置。

导出目标包括原始代码、普通 Markdown、HTML/PDF 样式、Hugo `hl_lines`、Expressive Code 行标记。复杂多色文本批注导出为代码后的说明列表；目标格式可承载的字段映射到对应参数。跨工具格式转换配套往返样例。

## 10. 核心验收示例

在 C 代码中标记危险调用的参数，在 Python 中标记一段控制流，在 ASM 中标记寄存器和地址；正文概念与这些代码标记归入同一“疑问”视图。插入前置代码后仍可定位；复制代码与原代码字符逐一相等；三个视图、软换行和移动端均能查看与操作。

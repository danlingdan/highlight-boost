# 连续选区与内置语法验证

日期：2026-11-14。原型 0.1.0。宿主使用 Obsidian 1.15.0 运行包与 Electron 38.8.6。

## 本轮交付

### 连续跨正文与代码块选区

一次选择可以覆盖正文和多个代码块，统一应用语义、改色及移除，操作一次撤销和重做。解析器提供正文可编辑范围，保留标题、列表、任务框、引用、callout 头、表格结构、代码围栏和语言参数。前置属性、注释、HTML、图片与行内代码按各自区域处理。

代码继续只改围栏外元数据。覆盖 CRLF、Unicode、多块代码、重叠选区、移除与重新解析；原有分离多选区操作继续保留。

### Shiki 源码合入

按项目要求，将 Shiki Highlighter 的主题、Expressive Code 配置与展示样式源码合入 HB；由 HB 的 `src/syntax/` 维护引擎、编辑器和宿主接入。特别感谢 Moritz Jung 及其贡献者，完整来源、原作者版权和引擎致谢见 [第三方声明](../../THIRD_PARTY_NOTICES.md)。

设置新增“语法着色”：宿主 / 内置 Shiki。更改后重新启用 HB 生效。默认使用宿主；选择内置 Shiki 后，HB 提供语法、预览组件、复制和标注层。

实现路线：

- 通过公开 `registerMarkdownCodeBlockProcessor` 同时接入阅读和 Live Preview 组件。
- 编辑器着色复用 HB 的 Markdown 解析和逻辑代码映射，初次打开即可定位代码区域。
- 文档、选区、视口变化均安排更新；每次请求带有代次标识，旧异步结果在代次变化后结束。
- 组合输入期间映射已有装饰，结束后重算；装饰通过视图更新提交，保持撤销历史。
- 每个预览组件单独挂接 HB 标注层，读取活动编辑器中的当前文本。
- 将 Expressive Code 空行的占位换行转换为逻辑空行，后续范围按源代码偏移计算。
- 构建时合入展示交互脚本，并将第三方完整 MIT 声明写入 `main.js`；构建产物同时附带致谢与许可证文件。

内置引擎版本：Shiki 3.23.0、Expressive Code 0.41.7。语法与展示的源码及依赖统一由本仓库管理。

## 上游 0.8.0 问题对照

上游 [#91](https://github.com/mProjectsCode/obsidian-shiki-plugin/issues/91) 报告 0.8.0 的完整 Live Preview 组件注册回归。源码中，阅读路径通过底层后处理注册，编辑器路径使用独立 CM6 mark 装饰；初始解析、选区变化和异步结果取消后的补算也会影响编辑器颜色。

项目用相同 SQL、ABAP、ASM 样例，分别在 Shiki 单独启用和同时启用 HB 时记录观察：

| 观察 | 0.7.7 | 0.8.0 |
| --- | --- | --- |
| 冷打开 Live Preview 组件 | 有 | 无 |
| Expressive Code 复制按钮 | 有 | 无 |
| 0.8.0 冷打开编辑器 inline color | — | 三种样例均未出现 |
| 仅移动光标或滚动 | 保持组件 | 仍无组件，冷打开缺失的颜色未恢复 |
| 编辑或重新进入视图 | 保持组件 | 部分场景出现 inline color，组件仍缺失 |
| 阅读视图完整组件 | 有 | 有 |

观察数据：[0.7.7](host-shiki-live-077-results.json)、[0.8.0](host-shiki-live-080-results.json)。各 32 项断言核对固定版本、隔离环境、源文本、编辑撤销和阅读路径；Live Preview 的差异保存在 observations 字段。

第三轮语言表中的“着色”表示原生 token 或 Shiki inline color 至少一种存在；该表在执行标注操作后采样。第四轮将二者与完整预览组件分别记录在 `editorRendering` 中，并增加冷打开对照。此前的静态着色结果继续作为样例观察，Live Preview 组件改用本轮专项结果。

# 中英文界面验证

验证日期：2026-11-14。Obsidian 1.15.0，隔离 Electron 38.8.6。

## 实现范围

设置提供跟随 Obsidian、中文及 English。自动模式识别中文，其余使用英文。命令、右键菜单、设置、侧栏、颜色选择器、提示、元数据折叠按钮和无障碍标签使用同一组语言目录。切换时更新已打开的界面与侧栏标签，命令 ID 保持稳定。

内置 Expressive Code 组件同步更新复制提示、复制完成提示、终端标题及折叠提示，代码内容与复制数据保持原样。重新渲染会清理旧的阅读标注子组件。

默认语义名称按界面语言显示。配置中的原始名称不因切换被改写；用户编辑名称后记录 `customName: true`，即使输入与默认中文名称相同，也按自定义名称保留。已有正文、行内代码和代码块的名称快照保持原文，新标注保存操作时显示的名称。

配置沿用 schemaVersion 2，增加 `language` 和可选名称标记；旧配置规范化与重复读取保持一致。初始化时记录当前语言，首次编辑预设不会触发设置页重建。

## 验证结果

`pnpm check` 通过：lint、类型检查、16 个测试文件中的 99 项测试及构建。新增测试覆盖中英文键和占位符一致性、单次插值、自动语言、自定义名称、双语颜色检索、错误提示、配置迁移、CodeMirror 控件重配置，以及内置代码组件文案和复制数据。

宿主场景共 294 项检查通过：既有 11 个场景 249 项，语言切换 35 项，独立进程恢复 10 项。完整场景运行后，恢复场景单独复核了新增的连续输入检查。

- [语言切换结果](host-i18n-results.json)：通过实际设置控件切换语言，检查命令、侧栏与标签、元数据、选择器、提示、名称快照、代码组件、原文及运行时错误。
- [重启结果](host-i18n-restart-results.json)：检查语言和自定义名称恢复、英文命令、源文逐字符一致、侧栏快照、首次编辑保留原控件、连续输入及配置还原。

隐藏宿主的设置输入框未取得真实焦点，连续输入检查验证原控件身份与后续输入保存。原生代码语言矩阵记录本次观察，C 阅读视图的 token 探测为 false；该项观察不属于界面语言验收。

两条语言场景的宿主控制台还输出了 `Uncaught illegal access`；场景的 `window.error` 收集为空，所有断言完成。这条控制台信息尚未定位来源，后续宿主兼容检查继续跟踪。

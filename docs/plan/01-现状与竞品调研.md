# 现状与竞品调研

## 1. Obsidian 原生能力

官方 [1.14.0 更新说明](https://obsidian.md/changelog/2026-09-02-desktop-v1.14.0/) 与[格式语法](https://obsidian.md/help/syntax)确认六色正文高亮、输入提示和光标内色板。基础格式为 `==文本==`，彩色格式如 `==🔴文本==`。正文颜色选择已经成为应用基础能力。

代码块由围栏及语言名表达；官方语法文档说明语法着色使用 Prism。编辑视图扩展采用 CodeMirror 6，阅读视图采用 Markdown 渲染后处理。两个视图的语言支持和 DOM 结构需要分别验证，语法配色与人工重点标记也需要分别建模。[官方扩展文档](https://docs.obsidian.md/Plugins/Editor/Decorations)

研究据此形成三类对象：正文高亮、行内代码重点、代码块标注。代码里的 `==`、HTML 标签和注释首先是代码内容；解析器根据所在语法区域选择对应规则。

### 源码抽样得到的具体结论

Colorful Highlights 的 `src/highlight-actions.ts` 将相交的正文高亮扩成并集后重新包装。这提供了明确的对照行为：本项目选择“精确选区改色”，使选区外的原高亮得到保留，配套测试覆盖拆分与合并。

其编辑扩展与阅读渲染分别位于 `src/extensions/color-highlight-extension.ts`、`src/reading-renderer.ts`。后者读取原生 `data-highlight`，并处理嵌套文本节点。由此将渲染适配集中封装，DOM 识别结果与源文本范围分开管理。

Sidebar Highlights README 已描述颜色分组、检索、集合和脚注。其公开问题 [#131](https://github.com/trevware/obsidian-sidebar-highlights/issues/131) 提到默认色被当作黄色的问题。本项目数据层保留 `default` 与 `yellow` 两个身份。

Highlightr [#112](https://github.com/chetachiezikeuzor/Highlightr-Plugin/issues/112) 报告独立设置窗口的控件显示问题。报告中的原因分析属于提交者判断；本项目采用标准 Setting 控件，并纳入多窗口验收。

## 4. 高亮引擎与其他内容来源

| 方案 | 适合解决的问题 | 采用方式 |
| --- | --- | --- |
| 宿主语法着色 | 与当前 Obsidian 一致、依赖较少 | 首版基础路线；重点层保留 token 颜色 |
| Prism | 语言语法、已有阅读视图 token | 使用宿主输出；自定义语言按后续需求扩展 |
| Shiki / TextMate | VS Code 类主题、较丰富语法、跨视图一致性 | 独立实验，测量体积、初始化与移动表现后接入 |
| Expressive Code | 标题、行标记、diff 和代码展示生态 | 研究导入导出与第三方协作 |
| [PDF++](https://github.com/RyotaUshio/obsidian-pdf-plus) | PDF 选择链接、批注与回链 | 后续统一来源卡片接入 |
| [官方 Web Clipper](https://github.com/obsidianmd/obsidian-clipper) | 网页采集与高亮来源 | 首版直接处理采集后产生的 Markdown |

Shiki 使用 TextMate 语法；Prism 采用自身语言定义及扩展机制。[Shiki 文档](https://shiki.style/guide/)、[Prism 扩展文档](https://prismjs.com/extending.html)。替换语言着色引擎会扩大加载与维护成本，先完成重点层，再依据样例决定语法引擎扩展。

## 5. 产品机会与路线选择

研究结论：正文调色、代码美化和高亮侧栏都已有产品。Highlight Boost 的组合价值定为：同一套语义贯穿正文与代码，选区操作准确，代码保持可复制，批注和摘录带来源，编辑后仍可找回。

三条实现路线：

1. 扩展现有插件：可较快改进局部行为，适合单一功能贡献。
2. 只做代码重点层：范围集中，正文体验交给其他插件，统一侧栏需要额外接口。
3. 新建统一插件：共享模型、命令和导出流程，覆盖正文及代码。**本项目选择此路线**，按原型、核心、集成阶段推进。

采用自主实现，并记录依赖来源。研究借鉴产品行为与公开 API；代码复用按对应文件许可证处理。Code Styler 的 GitHub 许可识别字段为 NOASSERTION，实际 LICENSE 为 MIT，并包含原始贡献者声明，复用时一并保留。

## 6. 首批用户场景

- 技术学习：正文概念与代码关键行归入同一“重点”视图。
- 代码阅读：对一个调用的参数标记“疑问”，附解释，再跳回准确位置。
- 教学分享：同一代码块标出关键步骤、变化行，导出带标注说明的讲解材料。
- 笔记整理：合并某目录内的概念与代码摘录，保留语言、文件名和回链。
- 日常复习：按语义筛选待理解内容，记录已掌握状态。

以上为产品设计场景；用户访谈与可用性验证在实施阶段补充。

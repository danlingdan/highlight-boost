# 批注与正文脚注

2026-11-14：阶段 F 批注模块采用 v1 可选字段扩展。原有必需字段、颜色、身份、范围和附着规则保持原样；旧笔记继续直接读取。

## 正文

正文 `hbp` 元数据增加可选 `noteRef`，指向标准 Markdown 脚注 ID。批注正文保存在脚注定义中，以定义内容作为读取来源。

```markdown
==概念==%%hbp:{"v":1,"id":"mark-example","semantic":"important","label":"重点","noteRef":"hb-example"}%%[^hb-example]

[^hb-example]: 第一段说明。

    第二段 **Markdown** 说明。
```

脚注采用 Obsidian 的[标准脚注语法](https://obsidian.md/help/syntax#Footnotes)。新增 ID 使用 `hb-` 与 UUID；追加定义遵循源笔记的 LF 或 CRLF，多行内容缩进四格。

普通原生高亮首次添加批注时获得持久 ID，原颜色保持不变；语义记录为 `color:颜色`，名称使用当前界面的颜色名称。已有语义标注保留身份与名称快照。

- 改色和改语义保留脚注引用。
- 局部拆分的片段共用原脚注；更新其定义会反映到引用片段。
- 清空一个片段的批注时解除该片段引用；若其他片段仍关联，保留定义和可见引用。
- 清空独占批注会移除 HB 引用和定义。外部引用及普通用户脚注保持原样。
- 移除正文高亮后，标准脚注仍作为笔记内容保留。
- 定义被手动删除后，可再次保存说明重建，或清空批注移除断开的引用。

## 行内与围栏代码

`InlineMetadata` 和 `CodeMark` 增加可选字符串 `note`。行内字段继续通过 `hbi` 编码 `%`、`|` 和反引号；围栏代码的说明仍位于围栏外的 `hb` JSON 中。

```json
{"id":"mark-example","kind":"text","from":0,"to":3,"quote":"mov","prefix":"","suffix":" ax, bx","color":"yellow","semantic":"important","label":"重点","note":"寄存器间传送。"}
```

改色、语义变更和重新绑定保留批注。清空内容移除 `note` 字段；移除代码标注会移除该记录及其批注。代码中的字符、Tab、空白和逻辑行保持原样。

## 显示与编辑

侧栏提供“编辑批注”，多行文本框支持保存和取消。提交前核对源文件、条目身份、范围、语义和已有批注；发生变化时保留输入草稿，并提示刷新。一次保存是一个编辑器事务，可以一次撤销和重做。

Source 显示完整脚注和元数据。Live Preview 将关联引用一同收起，并以可展开摘要显示 HB 脚注定义；点击或使用键盘展开源文。阅读视图通过宿主显示标准脚注。代码组件在 `pre` 外显示可展开说明，代码元素文本保持原样；编辑器重点和行内代码提供批注悬浮说明。

侧栏和代码旁说明使用文本 DOM 显示内容。正文脚注和导出的 Markdown 按宿主 Markdown 规则显示。HB 脚注定义中的高亮和代码不作为新的源标注进入索引。

## 检索、集合与导出

统一对象使用可选 `note` 表示当前说明。检索覆盖批注文本；集合在加入时保存批注快照，源条目可定位时读取当前说明，缺失时保留快照。各摘录模板及生成笔记均附带批注。

验证见 [批注模块记录](../verification/annotations.md)。

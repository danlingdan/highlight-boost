## 2. 阶段 A 的实验清单

| 实验 | 比较内容 | 通过证据与后续动作 |
| --- | --- | --- |
| A01 | 原生默认色与显式黄色的源文本/DOM | 固定样例与截图，冻结 ColorKey |
| A02 | 正文部分覆盖与邻接合并 | 输入/输出文本和一次撤销记录 |
| A03 | HB 注释在顶层、列表、引用和 callout 的关联 | 源偏移到逻辑行的对照表 |
| A04 | 编辑后锚定，特别是同文重复代码 | 成功、歧义及待定位样例 |
| A05 | 阅读 token 树的行背景方案 | 跨行 token、软换行、空行、复制对照 |
| A06 | CM6 注释折叠及 mark 装饰 | 光标、选择、输入法、撤销记录 |
| A07 | Shiki Highlighter 和 HB 重点层共存 | 实际 DOM、重渲染次数与交互结果 |
| A08 | C/Python/ASM 等语言在三视图显示 | 语言覆盖表、别名表和截图 |

实验结果影响存储格式时，先更新 schema 与样例，再进入后续核心实现。阅读视图中直接拖选创建标注需要独立验证 DOM Selection→源范围映射：通过后纳入增强入口，编辑器和侧栏命令始终作为基础操作路径。

## 3. 工程取舍与处理方式

| 事项 | 处理方式 |
| --- | --- |
| 宿主 DOM 随版本演进 | 集中适配、固定源映射样例，按支持版本回归 |
| 代码行号随编辑改变 | 行列作为提示，quote 与上下文参与重定位 |
| 原句已被改写 | 保留摘录，侧栏提供重新选择目标 |
| 多插件同时管理代码结构 | 设置语法和展示拥有者，按模块开启 HB |
| Markdown 嵌套结构丰富 | 公共解析核心、容器源映射与差分样例 |
| 全库扫描与查询性能 | 功能完成后统一测量，再调整调度、缓存与索引结构 |
| 配置同步与笔记同步不同 | 语义快照随笔记，配置提供导入导出 |
| 格式迁移量大 | 预览计数、逐文件执行、记录可恢复结果 |
| 需求继续扩展 | 优先交付统一标注闭环，扩展逐项增加验收 |

## 4. 文档更新约定

决定变化时写清新行为、选择原因、受影响格式与验证证据。阶段完成后在 `docs/verification/` 保存结果，并回填本目录状态。阶段推进依据交付物和验收记录。
